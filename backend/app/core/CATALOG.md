# Catalogo de elementos reusables del nucleo (`backend/app/core/`)

Una fila por elemento reusable. Antes de crear un schema, dependencia o
utilidad nueva en un modulo, revisa esta tabla (ver skill
`backend-reusable-core`).

| Elemento | Archivo | Firma / uso | Usado por |
|---|---|---|---|
| `get_settings` | `core/config.py` | `Settings` (pydantic-settings) leida de `backend/.env`; unico punto de acceso a variables de entorno | todo el backend |
| `Settings.cors_origins_list` | `core/config.py` | parsea `CORS_ORIGINS` (string separado por comas) a `list[str]`; consumido por `CORSMiddleware` en `app/main.py` | `app.main` |
| `get_session` | `core/database.py` | dependencia de sesion async por request (`AsyncSession`) | todos los routers |
| `Page[T]` | `core/schemas.py` | `Page[StaffRead]` — respuesta paginada generica (`items`, `total`, `page`, `page_size`) | todos los listados |
| `ErrorResponse` | `core/schemas.py` | `{code, message, details}` — formato unico de error | todos los handlers de error |
| `AppError` / `NotFoundError` / `ConflictError` / `ValidationAppError` | `core/exceptions.py` | excepciones base que el controller lanza sin conocer HTTP; `register_exception_handlers(app)` las traduce a `ErrorResponse` + status code | todos los modulos |
| `not_found` | `core/exceptions.py` | `raise not_found("un examen", id)` -> 404 `not_found` "No existe un examen con id 'X'.", `details={"id": X}`; `scope=" para la etiqueta 'P'"` y `parent={"print_label_id": P}` para recursos hijos (antes habia una clase `*NotFoundError` por entidad) | `get_or_404` y los controllers de todos los modulos |
| `PaginationParams` / `pagination_params` | `core/dependencies.py` | `page`, `page_size` como query params (`page_size` <= ajuste `pagination.max_page_size`, 200 por defecto, leido por peticion; 422 si se excede); expone `.offset` / `.limit` | todos los listados |
| `ActiveOnlyFilter` / `active_only_filter` | `core/dependencies.py` | filtro `?active=true` sobre catalogos con columna `is_active`; `active=None` = sin filtrar. `active_filter.apply(stmt, Model.is_active)` agrega el `WHERE` (unico lugar; no se reescribe por modulo) | todos los listados de catalogo |
| `SearchFilter` / `search_filter` / `NO_SEARCH` | `core/dependencies.py` | `?q=` (max 100, descripcion en el OpenAPI): `search.apply(stmt, Model.code, Model.name)` -> AND entre palabras (max 8), OR entre columnas, sin mayusculas ni tildes (`normalized`/`normalized_pattern` de `core/db/search.py`), `%`/`_`/`\` escapados; sin texto no toca el `stmt`. Se aplica antes de `paginate`, asi `total` refleja el filtro. Controllers/repositories reciben `search: SearchFilter = NO_SEARCH` | todos los listados de catalogo (staff, lab_areas, lab_tests, preconditions, samples y sus tipos, print_labels, consent_documents, units, analytes, option sets y sus opciones, result_templates) |
| `include_inactive_param` | `core/dependencies.py` | `?include_inactive=true` (default `false`) en listados de contenido que se desactiva en vez de borrarse | lab_tests (colecciones), result_templates (secciones, analitos, rangos) |
| `paginate` | `core/repository.py` | `items, total = await paginate(session, stmt, pagination, *order_by)`; cuenta las mismas filas del `stmt` con `SELECT 1` (no nombra columnas pesadas como `file_base64`) | todos los listados paginados, `/activity` |
| `get_or_404` / `create_entity` / `update_entity` | `core/repository.py` | `await get_or_404(session, Model, id, "un examen")` -> fila o 404 `not_found`; `await create_entity(session, Model, data, **extra)` (`Model(**data.model_dump(), **extra)` + commit + refresh; `extra` = FK del padre, `kind`...); `await update_entity(session, entity, data)` PATCH generico: `exclude_unset`, excluye `activity_reason`, `flush_with_reason` solo si el PATCH trae `is_active`, commit y refresh. Los controllers los llaman directo: los repositories no llevan wrappers | todos los controllers |
| `get_by_ids` | `core/repository.py` | `await get_by_ids(session, Model, ids) -> {id: fila}` en una consulta (se llama directo desde el controller) | lab_tests, result_templates |
| `sync_collection` | `core/repository.py` | reemplazo de un set completo sin `DELETE`: desactiva lo quitado, reactiva la misma fila de lo que vuelve, inserta lo nuevo (sin commit) | lab_tests (`PUT` de precondiciones, tipos de muestra, documentos) |
| `ActivityReasonInput` | `core/schemas.py` | mixin de los `XUpdate` con `is_active`: `activity_reason: str \| None` (<=255), motivo de (des)activacion guardado en `activity_events.reason` | todos los `XUpdate` con `is_active` |
| `flush_with_reason` | `core/activation.py` | fija `vladimir.activity_reason` (local a la transaccion, sin autoflush) y hace `flush`; no lo limpia (lo cierra el commit que sigue). Llamar solo si hay cambio de `is_active` | `update_entity` |
| `ensure_active` / `ensure_active_reference` / `InactiveReferenceError` | `core/activation.py` | `ensure_active(entity, subject="el analito", field="analyte_id")` -> 422 `inactive_reference` "El analito «GLU» está inactivo."; `ensure_active_reference(entity_or_none, ..., value=id)` agrega 422 `invalid_reference` si no existe. Solo para referencias NUEVAS | todos los modulos |
| `get_active_by_id` | `core/activation.py` | `await get_active_by_id(session, Model, id)` -> fila o `None` si no existe o esta inactiva | lab_areas (encargado) |
| `InvalidReferenceError` | `core/exceptions.py` | 422 `invalid_reference`: "La unidad con id 'X' no existe." (`reason=` cambia el final); `details={field: id}` | result_templates, `ensure_active_reference` |
| `db_error_handler` | `core/exceptions.py` | SQLSTATE `VLD01` (DELETE bloqueado por BD) -> 409 `delete_forbidden`, `details.table`; registrado en `register_exception_handlers` | toda la API |
| `activity_router` / `ActivityEventRead` / `ACTIVATABLE_TABLES` | `core/activity.py` | `GET /api/v1/activity?entity_type=&entity_id=` paginado, mas reciente primero; `entity_type` enum = tablas con `is_active` (test contra `Base.metadata`) | `app.main` |
| fixtures `session` / `client` | `app/conftest.py` (solo tests) | BD real en transaccion revertida + cliente httpx; los `conftest.py` de los modulos ya no las redefinen | tests de todo el backend |
| `VersioningService` | `core/versioning.py` | Ciclo completo de versiones `draft`->`published`->`retired`. Cada modulo lo instancia UNA vez en su `controller.py`: `VersioningService(VersionModel, "parent_fk", parent_model=, parent_noun="etiqueta", feminine=True, read_schema=XVersionRead, owner_read_schema=XVersionWithOwnerRead, required_fields=(...campos de la version 1), publish_required={campo: atributo_indicador} (422 al publicar si el indicador es None; lo usa consent_documents), validate_publish=hook opcional, clone_content=hook opcional)` y rebinda `list_versions = versioning.list_versions` (+ `create_version`, `update_version`, `publish_version`, `retire_version`, `get_version_with_owner = versioning.read_with_owner`, `get_version = versioning.read_version` (XVersionRead del padre, sin commit; estado previo para auditar)) para las rutas. Casos de uso (con commit): listar con `?status`, crear (version 1 / clonar con overrides, un solo borrador, padre activo), editar, publicar (`validate_publish` antes), retirar (409 `version_in_use`). Utilidades: `get_or_404(session, parent_id, version_id)` (404 si no pertenece al padre), `get_draft` (+ 422 si no es borrador). Bajo nivel (solo flush): `create_draft`/`ensure_draft`/`publish`/`retire`. Los mensajes en espanol salen de `parent_noun`/`feminine` | print_labels, result_templates (hooks `validate_publish` + `clone_content`), consent_documents |
| `CodeStr` / `CODE_MAX_LENGTH` | `core/schemas.py` | `code: CodeStr` / `code: CodeStr \| None = None` — `str` con `max_length=64` (`CatalogMixin.code`) | todos los schemas de catalogo (lab_areas, lab_tests, preconditions, samples, print_labels, result_templates, consent_documents) |
| `VersionStatus` | `core/schemas.py` (reexportado por `core/versioning.py`) | `Literal["draft","published","retired"]` (= `VersionMixin.status_check()`); tipa `status` de los `XVersionRead` para que el OpenAPI lo exponga como enum | print_labels, result_templates, consent_documents |
| `register_version_usage` / `VersionInUseError` | `core/versioning.py` | inversion de dependencia: `lab_tests` registra `register_version_usage("<tabla_versiones>", finder)` con `finder = async (session, version_id) -> [codigos de examenes activos]`; `VersioningService.retire` lo consulta por `model.__tablename__` y lanza 409 `version_in_use` ("No se puede retirar la versión: la usan exámenes activos (A, B).", `details={id, lab_test_codes}` ordenados y sin duplicados). Idempotente por tabla; mensaje y clave de `details` fijos (un solo consumidor) | lab_tests (registra, desde `app/main.py`), print_labels/result_templates/consent_documents (via `retire`) |
| `VersionMissingFieldsError` / `VersionDraftExistsError` | `core/versioning.py` | 422 "Faltan campos obligatorios para crear la primera version: a, b." (o `action="publicar la version"`; `details.missing_fields`) y 409 "La etiqueta 'id' ya tiene un borrador; edítalo en vez de crear uno nuevo." (`details={<parent_fk>: id}`); los lanza `VersioningService.create_version` | print_labels, result_templates, consent_documents |
| `VersionOwnerRead` | `core/versioning.py` | `{id, code, name, is_active}` del catalogo dueno de una version; campo `owner` de los `XVersionWithOwnerRead` | print_labels, result_templates, consent_documents |
| `version_status_param` | `core/dependencies.py` | `?status=draft\|published\|retired` (`VersionStatus \| None`) en los listados de versiones; el repository agrega el `WHERE` si no es `None` | print_labels, result_templates, consent_documents |
| `DuplicateValueError` / `CodeConflictError` | `core/exceptions.py` | 409 con mensaje en espanol natural: `CodeConflictError("un área", code)` -> "Ya existe un área con el código «X»."; `DuplicateValueError(entity=, field=, field_label=, value=)` para otras claves unicas. `details` siempre usa el nombre tecnico del campo (`{"code": ...}`); `scope=` / `extra_details=` para unicidad dentro de un padre | todos los controllers (ya no hay una clase `*CodeConflictError` por modulo; el numero de documento de `staff` usa `DuplicateValueError` directo) |
| `test_exception_contract` | `core/tests/test_exception_contract.py` (solo tests) | tabla `(constructor, status, code, mensaje, details)` de `not_found`/`CodeConflictError`/`DuplicateValueError` para cada entidad; un mensaje nuevo se agrega ahi | tests del nucleo |
| `schema_model_mismatches` / `enum_values` | `core/tests/schema_checks.py` (solo tests) | compara `maxLength`/enums del JSON Schema de un schema Pydantic con las columnas `String(n)` de su modelo; cada modulo lo usa en su `tests/test_schemas.py` | tests de todos los modulos |
| `error_responses` / `RequestValidationErrorResponse` | `core/schemas.py` | `@router.patch("/{id}", responses=error_responses(404, 409, 422))` — declara en el OpenAPI los errores de negocio (`ErrorResponse`; el 422 admite tambien el formato por defecto de FastAPI); `descriptions={409: "..."}` cambia un texto. Convencion: GET con `{id}` → 404; POST → 409/422 (+404 si hay `{id}`); PATCH → 404/409/422; PUT → 404/422; `publish` → 404/422; `retire` → `RETIRE_VERSION_RESPONSES` | todos los routers |
| `MINIMAL_PDF` / `pdf_base64` / `pdf_sha256` | `core/tests/pdf.py` (solo tests) | PDF minimo valido para la validacion de archivos y su base64/hash | tests de consent_documents, lifecycle, lab_tests |
| fixture `no_active_general_consent` | `app/conftest.py` (solo tests) | desactiva (en la transaccion revertida) el consentimiento general `tratamiento_datos` de la BD de desarrollo, para tests que crean el suyo | tests de consent_documents y lab_tests |
| `RETIRE_VERSION_RESPONSES` | `core/versioning.py` | `responses=` de `POST .../versions/{id}/retire` con el 409 `version_in_use` | print_labels, result_templates, consent_documents |

Convencion de enums: en el `schemas.py` de cada modulo, `X = Literal[X_VALUES]` derivado de la tupla del CHECK en su `models.py` (fuente unica de valores; no se reescriben a mano).
| `auth` / `catalog` / `record_audit` | `core/leo.py` | Integración con Leo (`leo_sdk`): `auth` (`LeoAuth`), `catalog` (`Catalog("vladimir")`). Cada módulo protegido tiene `permissions.py` que declara su módulo+acciones en `catalog` y expone `CanX = Annotated[LeoUser, auth.require_action(tag)]`. `await record_audit(tag, user, entity_type=, entity_id=, before=, after=, reason=)` registra evento con `diff`; un fallo de Leo se loguea y no propaga. Para PATCH con `is_active`: `authorize_patch(request, user, data, edit_check=, status_check=)` (exige `edit` y/o `change-status` según el body) y `audit_patch(user, edit_tag=, status_tag=, entity_type=, entity_id=, before=, after=, reason=)` (evento de datos + evento de estado). `snapshot(read, *exclude)`: estado auditable de un `XRead` (JSON, sin id/timestamps ni los `exclude` anidados/derivados) para `before`/`after` | los 8 modulos de negocio (lab_areas, staff, lab_tests, preconditions, samples, print_labels, result_templates, consent_documents); `app.main` (`auth.install`, `leo_router`, `check_catalog` en lifespan) |
| `leo_sync` | `core/leo_sync.py` | `uv run python -m app.core.leo_sync [--deactivate-missing]` publica el catálogo en Leo (paso de despliegue; no se hace al arrancar) | despliegue |
| fixtures `leo` / `FakeLeo` | `app/conftest.py` (solo tests) | `leo.user` (`None` = 401; por defecto todos los tags), `leo.grant(*tags)`, `leo.events` (auditoría capturada), `leo.down`; `client` ya sustituye `auth.current_user` | tests de módulos protegidos |
| `runtime_settings` (`get`, `store`, `VLADIMIR_SETTINGS`) | `core/runtime_settings.py` | Ajustes editables en BD (`leo_sdk.settings_store`): `await runtime_settings.get("files.consent_max_mib")` / `"pagination.max_page_size"`, leidos por peticion (cache ~10 s, invalidada al editar; si la BD falla, default).
